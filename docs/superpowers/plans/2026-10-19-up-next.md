# Up next Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mid-shop, one autopilot slip names the item on the list the house usually grabs next, learned from the order past runs were checked off; and autopilot's tiers and slips become one mapping and one front-to-back stack.

**Architecture:** A pure route learner in `analytics/predict` runs inside the house profile build and stores a per-list `Route` (spots 0..1 plus a backtested score). `internal/autopilot` gains the feature→modes table, the slip order and a Go twin of the pick rule. `GET .../autopilot` returns the ordered `stack`, the `up_next` route and the current run (from every member's check-offs); the List page reads only that view, renders one `SlipStack` (display-only peeks) and runs the pick rule client-side for instant hand-off.

**Tech Stack:** Go 1.26 (`chi`, MongoDB), React + Vite + TypeScript, TanStack Query, MSW mock, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-19-up-next-design.md` (read it with this plan).

## Global Constraints

- `internal/autopilot` stays pure; `analytics` never imports `autopilot`. The route learner lives in `analytics/predict` (no `parse` import there; merging happens in `analytics/profile.go`).
- Up next is on **Suggest and Assist**; never Off. Features ask `autopilot.Has`, never compare modes.
- One autopilot slip at a time. Stack order `up_next > auto_add > suggestions`. Peeks are display-only (`aria-hidden`, not focusable), at most 2.
- `✕` on Up next is client-only, keyed to the run, 12 h ceiling; it never emits a forecast signal.
- No yellow key on the Up next slip. CSS uses tokens only; `Button`/`Paper` primitives only; no Ant Card/Button/Modal.
- User copy: "Up next", "Usually next · then <name>", `title="Not now"`, `aria-label="Hide up next"`, tick label "<name>, done", announcement "Up next: <name>".
- Route bars: ≥ 5 qualifying runs of ≥ 4 distinct keys; window 12 runs; half-life 4 runs; hit = named key checked within next 2 checks; score = Wilson lower bound; `UpNextMinScore` starts at 0.5 and is set by the eval.
- Ship bar (synthetic, pinned by tests): hit rate ≥ 70% where it speaks; silent on two-store and random personas. Real-data run is a **deploy** gate, not a merge gate.
- The existing golden world (`world.golden.json`) and autopilot benchmark numbers must not change.
- Commits: `feat(autopilot): …`, `feat(up-next): …`, `feat(ui): …`, `docs(up-next): …`; end each with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. `make check` before every commit.

## Review Focus

1. **Leftover checked rows from last week** (house never clears): they must never anchor the route. Test in Task 6 (`TestUpNextRunIgnoresOldChecks`).
2. **A list item with no route spot checked mid-run** (new thing): the anchor stays put and that item is never named. Case in the shared fixture (Task 4).
3. **Two items whose names are look-alikes** ("egg"/"eggs") both on the list: one spot, both items map to it; the pick names the unchecked one. Test in Task 6 (`TestUpNextRouteMapsLookAlikes`).
4. **Profile recomputed mid-shop moves `NextRun` to next week:** `ready` stays true while a run is in progress. Test in Task 6 (`TestUpNextReadyLatchesDuringRun`).
5. **House switches mode to Off mid-shop:** the next view has no `up_next` and no stack entry; the page drops the slip. Test in Task 6 (`TestViewOffHasNoStack`) and Task 10 (`hides up next when the stack drops it`).
